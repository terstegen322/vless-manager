# VLESS Vault — Серверлесс-менеджер подписок (Happ / Invy)

Бесплатная система управления персональными VLESS-ключами через связку:
1. **GitHub Pages (Web UI)** — мобильное PWA-приложение для телефона (`index.html`).
2. **GitHub Gist** — база данных ключей (`all.txt`, `favourites.txt`, `config.json`, `db.json`).
3. **GitHub Actions** — автоматический TCP-пинг серверов каждые 6 часов и отсев молчащих узлов (`check_keys.py`).

## Папка «Хаб» — карантин для новых ключей

Чтобы не пинговать в Happ / Invy огромный `all.txt`, новые ключи сначала попадают в **Хаб** (`hub.txt`):

1. Вставляете пост из Telegram — ключи добавляются в Хаб и в архив «Все». В Хаб идут только **новые** ключи:
   уже известные из «Все» и «Любимых» пропускаются.
2. В клиенте подписываетесь на RAW-ссылку Хаба и пингуете только его.
3. Рабочие отмечаете **★ В Любимые**.
4. Остальные живут в Хабе заданное число дней (по умолчанию **7**, меняется на вкладке «Хаб»), затем GitHub Actions
   убирает их из Хаба. В «Все» они остаются.

Правила очистки:
- **Хаб** — только по сроку пребывания в Хабе (`hub_added_at`), а не из-за TCP-пинга с GitHub. Ключ, давно лежавший в «Все»
  и перенесённый кнопкой «🗂 В Хаб», получает полный срок. Срок отсчитывается с первой проверки после попадания в Хаб (≈ до 6 ч).
- **«Все» и «Любимые»** — защищённые папки, автоматически не чистятся.
- **Пользовательские папки** — по «молчанию»: ключ удаляется, если не отвечает дольше заданного числа дней.

Названия подписок в Happ / Incy:
- Клиент берёт название не из URL (`#Хаб` в ссылке на него не влияет), а из HTTP-заголовка `profile-title` или из первой строки
  файла `#profile-title: Название`. Gist заголовки не отдаёт, поэтому эта строка пишется в начало каждого `.txt`
  (интерфейсом при сохранении и чекером при каждой проверке). Кириллица кодируется как `base64:…`, длина — до 25 символов.
- Названия папок хранятся в `config.json` (`titles`). Если подписка уже добавлена в клиент — обновите её (pull-to-refresh /
  «обновить подписку») или добавьте заново: название подхватывается при обновлении.

Безопасность данных:
- Приложение дочитывает файлы Gist больше 1 МБ по `raw_url` и не даёт сохранять, пока данные не загружены.
- Если Gist изменился после загрузки (например, отработала проверка), перед сохранением будет вопрос, а не молчаливая перезапись.
- Кнопка «Проверить пинг» запускает workflow — токену нужны права `gist`, `repo` и `workflow`.

## Быстрый старт

### 1. Настройка секретов репозитория
Перейдите в **Settings → Secrets and variables → Actions** и добавьте два секрета:
- `GIST_TOKEN` — ваш GitHub Personal Access Token с правами `gist`.
- `GIST_ID` — `b9afa5ebb9d442f8a031e183f90cbaa2`.

### 2. Включение GitHub Pages
Перейдите в **Settings → Pages**:
- **Source:** Deploy from a branch
- **Branch:** `main` / `root`
- Нажмите **Save**.

Откройте полученную ссылку на телефоне и сохраните на домашний экран как PWA.
